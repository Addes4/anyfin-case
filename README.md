**Run:** `uv run classify.py data/validation.csv` (any CSV path works) writes `predictions.csv`; set `OUT=name.csv` to rename it. The API key is read from `ANTHROPIC_API_KEY` or a `.env` file. The command exits with code 1 if API failures left rows unclassified. `uv run classify.py --eval` scores it leave-one-customer-out, and `uv run test_classify.py` runs the edge-case tests (no API needed).
**Approach:** deterministic rules for structure: own-account moves are paired only when both rows look like transfers and the match is unambiguous, plus rules for savings, card bills, salary, cash, Swish with a clear message or none, loans and collections. Everything else goes to Claude Opus 5.5 at low effort as unique merchant keys (merchant text, money in/out, amount band, account type, whether it recurs monthly; private names removed), in batches of 60, with training rows as examples. The model answers `unknown` when unsure.
**Measured:** leave-one-customer-out on training scores 100.0, including 100.0 on the 636 rows whose merchant is unseen in the other customers. Rules label 22% of training rows and 20% of validation rows. A cold run on the validation set (1,183 rows, 347 unique model items) takes 12 s and costs ~$0.37; a warm re-run takes 1 s and costs $0. For 5,517 rows I estimate ~1 min and ~$1.75, extrapolated and not measured.
**Cost at 10M rows/month:** cold cost is ~$0.0011 per unique model item, about $0.0003 per row at this set's level of duplication. That gives a no-cache upper bound of ~$3,200/month on Opus, or roughly 1/40 of that on Haiku 5.5. With the persistent cache, cost scales only with new merchant keys (~$110 per 100k new keys). I have not measured the new-key rate at that volume.
**With another day:** turn the cache into a reviewed merchant table, calibrate `unknown` against held-out customers instead of the model's own confidence, test on more banks' formats, and send only the ambiguous rows to Opus while Haiku labels the rest.
